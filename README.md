# resume.austinhenry.dev

Source for [resume.austinhenry.dev](https://resume.austinhenry.dev) — Austin Henry, Infrastructure & Integration Engineer.

One JSON file is the resume. Everything else is derived from it and verified before it ships.

```
resume.json ──▶ scripts/build.mjs ──▶ dist/ ──▶ Cloudflare Workers (static assets)
                 │                       ├─ index.html, 404.html      resume.austinhenry.dev
                 │                       ├─ resume.json (verbatim)    ▲
                 │                       ├─ resume.pdf  (1 page)      │ terraform/: custom domain,
                 │                       ├─ og.png                    │ apex 301 → resume.
                 │                       ├─ fonts/ css/ js/ (hashed)  │
                 ▶ validate.mjs          └─ _headers (CSP, HSTS …)
```

## Pipeline

| Trigger | Workflow | What happens |
|---|---|---|
| pull request | `ci.yml` → `checks.yml` | ESLint · stylelint · `terraform fmt`/`validate` · build · PDF · OG · htmlhint · tests |
| pull request | `ci.yml` | **Workers Preview** at `pr-<N>`, URL pinned in a sticky PR comment · Lighthouse (mobile) scores in the job summary · Preview deleted on close |
| push to `main` | `deploy.yml` → `checks.yml` | same checks with `RELEASE=1` (any `TODO` left in `resume.json` fails the build) · `wrangler deploy` · smoke test |
| weekly + every PR | `security.yml` | Gitleaks · Dependency Review · CodeQL |
| weekly | Dependabot | npm, Actions and Terraform provider updates (minor/patch grouped) |

Secrets: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, and optionally `RESUME_PHONE` (see below).

### Dependabot policy

- Grouped minor and patch bumps (npm, GitHub Actions) are merged with a merge commit once all required checks are green, one at a time, updating the branch if it is behind `main`.
- Major bumps: read the release notes, check out the branch, and run `npm ci && npm run check:full` locally. For `wrangler` bumps also run `npm run deploy:dry` and confirm the PR preview serves `/` with the CSP header. For `playwright` bumps confirm `npm run pdf` still produces a 1-page PDF. Merge only if all pass; otherwise comment the failing command and leave the PR open.
- Terraform provider bumps: `cd terraform && terraform init -upgrade && terraform plan` must show no changes before merging. Never apply from a Dependabot PR.
- A red Dependabot PR is never merged to see whether `main` fixes it.

## What the build enforces

- `resume.json` validates against the [JSON Resume](https://jsonresume.org/schema) schema plus house rules: exactly one featured role, per-role highlight budgets, GitHub links for projects, balanced `**` markers.
- **No phone number anywhere on the web.** Not in the HTML, not in `/resume.json`, not in the JSON-LD. If the `RESUME_PHONE` secret is set, the PDF renderer injects it into a print-only slot at render time; nothing in git ever contains it.
- The only inline script (theme bootstrap) is allowed by SHA-256 hash in a `default-src 'none'` Content-Security-Policy; inline `style=` attributes are rejected by the build.
- Every local link and anchor resolves; `html + css + js + fonts` stay under 150 KB (fonts are ~88 KB of that).
- `resume.pdf` is exactly one Letter page, tagged, with title/author/keywords metadata.

## Working on it

```sh
npm ci
npm run check        # lint → build → htmlhint → tests
npm run check:full   # … plus PDF and OG (needs `npx playwright install chromium` once)
npm run watch        # rebuild on change
npm run dev          # serve dist/ with wrangler, including _headers
npm run deploy:dry   # what wrangler would upload
```

Content lives in `resume.json`. Highlights are plain strings; wrap a number in `**…**` to set it in the accent monospace. Each role has an `x-display` of `featured`, `compact` or `earlier`; the one-page PDF keeps the first few highlights of each role (`PRINT_LIMIT` in `src/templates/work.mjs`, overridable with `x-print-limit`), while the web page shows them all.

Templates are plain tagged-template functions in `src/templates/`; CSS is concatenated from `src/css/` in a fixed order; `src/js/main.js` is progressive enhancement only (theme toggle, current-section nav, reveal) — the page is complete without it.

## Headers

Served from `dist/_headers` (generated by the build):

`Content-Security-Policy` (`default-src 'none'`, self-hosted fonts, hashed inline script) · `Strict-Transport-Security` · `X-Content-Type-Options: nosniff` · `Referrer-Policy: strict-origin-when-cross-origin` · `Permissions-Policy` · `Cross-Origin-Opener-Policy` · `Cross-Origin-Resource-Policy` · immutable caching for hashed assets · CORS on `/resume.json`.

Reproduce the Lighthouse numbers against production:

```sh
npx lighthouse https://resume.austinhenry.dev --form-factor=mobile --view
```
